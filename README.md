# isaflow-bot

키움증권 ISA 계좌의 월배당 포트폴리오를 디스코드에서 관리하는 봇.
입력한 금액을 포트폴리오 비중에 맞춰 자동으로 리밸런싱 매수하고, 계좌 현황·미체결·분배금을 디스코드에서 조회한다.

봇이 다루는 종목은 `data/portfolio.json`에 적힌 것뿐이다. 같은 ISA 계좌에 다른 전략으로
매수한 종목이 있어도 주문을 걸지 않고, 비중·수익률·분배금 집계에도 섞지 않는다.
([전략 종목과 전략 외 종목](#전략-종목과-전략-외-종목))

PC에서 `start.vbs`를 실행하면 콘솔 창 없이 트레이 아이콘으로 상주하며, 디스코드 슬래시 커맨드로 사용한다.

## 명령어 한눈에 보기

| 명령어         | 기능                                          |
| -------------- | --------------------------------------------- |
| `/계좌현황`    | 전략 평가금액·손익·수익률·보유 종목·비중 괴리 |
| `/매수 [금액]` | 포트폴리오 비중대로 리밸런싱 매수 (확인 버튼) |
| `/미체결`      | 전략 종목의 미체결 매수 주문을 최신 호가로 재주문 |
| `/배당 [기간]` | 분배금 입금 내역 + 월별 추이 차트             |
| `/포트폴리오`  | 포트폴리오 구성 비율 차트                     |

## 명령어 사용 설명서

### `/계좌현황`

ISA 계좌의 상태를 한눈에 본다. 수치는 모두 **전략 기준**이다.
표시 항목: 전략 평가금액, 전략 매입금액, 매수 가능 금액, 전략 평가손익, 전략 수익률,
보유 종목 목록, 목표 대비 현재 비중 차트.

> "매수 가능 금액"은 미체결 주문이 차지한 금액을 제외한 실제로 매수에 쓸 수 있는 돈이다.
> 이 값만은 계좌 전체 기준이다 — 예수금은 전략과 무관하게 공유되기 때문이다.

전략 외 종목을 보유 중이면 아래에 `👀 전략 외 보유` 섹션과 계좌 전체 합계가 따로 붙는다.
비중 차트의 분모는 계좌 전체가 아니라 **전략 평가액 합**이다. 계좌 전체를 쓰면 전략 외
종목이 분모만 키워 모든 종목이 목표에 미달하는 것처럼 보인다.

### `/매수 [금액]`

입력한 금액을 포트폴리오 비중에 맞춰 자동 분배 매수한다. 2단계로 동작:

1. **리밸런싱** — 기존 보유분을 고려해 목표 비중에 가장 가까워지도록 1주씩 배분
2. **잔여금 소진** — 목표를 다 채운 뒤 남은 돈으로 가장 덜 채워진 종목부터 추가 매수

매수는 **매도1호가 지정가**로 진행되며, 확인 버튼을 거쳐야 실제 주문이 나간다.
주문 후 3초 뒤 체결 결과(전량 체결 / 일부 체결 / 미체결)를 다시 보여준다.

```
예) /매수 300000
```

### `/미체결`

조회 시점과 주문 시점 사이 호가가 바뀌어 체결되지 않은 매수 주문을 일괄 정리한다.

1. 미체결 매수 내역 조회
2. 전략 종목과 전략 외 주문을 가름
3. 전략 종목의 최신 매도1호가 조회
4. 확인 버튼 → 기존 주문 취소 → 최신 가격으로 재주문

미체결 주문이 없으면 "✅ 미체결 주문이 없습니다"로 안내하고 종료한다.

> **전략 외 주문은 건드리지 않는다.** 목록에만 `👀 전략 외 미체결`로 보여주고 취소도
> 재주문도 하지 않는다. 다른 전략으로 낮은 지정가에 걸어둔 주문을 매도1호가로 재주문하면
> 싸게 사려던 의도가 그대로 깨지기 때문이다. 그 주문의 취소·정정은 키움 앱에서 직접 한다.

### `/배당 [기간]`

ISA 계좌의 분배금(수익분배금입금) 입금 내역을 조회한다.
표시 항목: 월별·종목별 분배금 합계, 기간 총합, 월별 추이 차트.

**기간 입력 형식**

| 입력                    | 의미                   |
| ----------------------- | ---------------------- |
| `/배당`                 | 이번 달                |
| `/배당 2026-04`         | 특정 월                |
| `/배당 2026-01~2026-04` | 기간 (시작월~종료월)   |
| `/배당 전체`            | 전체 기간 (자동 탐색)  |

**전체 기간** — 최근 1년 구간부터 과거로 거슬러 올라가며 조회하되, 거래가 없는 구간이
2회 연속 나오면 멈춘다. 계좌 개설 이전까지 헛되이 호출해 유량제어에 걸리는 것을 막기 위함이다.

**표시 분량** — 디스코드 임베드는 필드 25개·전체 6000자가 한도다. 최근 10개월만 종목별로
펼치고 그 이전은 `📦 그 이전 N개월`로 접어서 보여준다.

**전략 외 분배금** — 전략 외 종목에서 분배금이 들어오면 월별 집계·차트에는 넣지 않고
`👀 전략 외 분배금` 필드에 종목별 합계만 따로 보여준다.

### `/포트폴리오`

설정된 포트폴리오 구성을 비율 차트와 함께 조회한다.
1F(안전판) / 2F(월세 수입) / 3F(인컴 엔진) 그룹별 비중과 각 종목의 분배율을 표시한다.

## 전략 종목과 전략 외 종목

ISA는 1인 1계좌라 계좌를 쪼갤 수 없다. 월배당 전략과 다른 전략을 한 계좌에서 굴리게 되는데,
그대로 두면 세 가지가 어긋난다.

- 비중 계산의 분모가 커져 전략 종목이 전부 "부족"하게 보인다
- 수익률·분배금 집계에 다른 전략의 성과가 섞인다
- `/미체결`이 다른 전략의 지정가 주문을 취소하고 매도1호가로 재주문해 버린다

그래서 **`data/portfolio.json`에 적힌 종목만을 "전략 종목"으로 보고**, 나머지는 전략 외로
가른다. 이 경계는 `core/portfolio.py`가 한 곳에서 정의한다.

| 구분           | 주문 | 비중·수익률 | 분배금 집계 | 화면 표시          |
| -------------- | ---- | ----------- | ----------- | ------------------ |
| 전략 종목      | O    | 포함        | 포함        | 본문               |
| 전략 외 종목   | X    | 제외        | 제외        | `👀` 참고 섹션     |

전략 외 종목을 전략에 편입하려면 `data/portfolio.json`의 `holdings`에 추가하고 `weight`
합이 1.0이 되도록 다시 배분한다. 추가하는 즉시 모든 명령어가 따라온다.

주의할 점이 둘 있다. **예수금은 공유된다** — 전략 외 매수로 현금을 쓰면 `/매수`의 매수
가능 금액이 줄고 증거금 부족 경고가 뜰 수 있다. **ISA 비과세 한도도 공유된다** — 전략 외
종목의 배당·매매차익이 같은 한도를 쓰므로, `/배당`의 전략 총계만 보고 한도 소진을
판단하면 어긋난다. 전략 외 분배금을 참고로 함께 보여주는 이유다.

> `data/portfolio.json`을 읽지 못하면 전략 종목을 **빈 집합**으로 둔다. `/미체결`의 재주문
> 대상이 0건이 되어 아무 주문도 건드리지 않는다. 잘못 읽은 목록으로 남의 전략 주문을
> 취소하느니 아무것도 안 하는 편이 안전하기 때문이다.

## 설치

요구 사항: Python 3.11+, [uv](https://docs.astral.sh/uv/), 키움 REST API 사용 신청, 디스코드 계정

```bash
cd isaflow-bot
uv sync
```

## 사전 준비

**1. 키움 REST API** — [키움 OPEN API](https://openapi.kiwoom.com)에서 신청 후 앱키·시크릿키 발급.
키움 마이페이지에서 **ISA 계좌가 기본 계좌로 설정**되어 있는지 확인한다.
(키움 API는 앱키 한 쌍이 한 계좌에 매핑되며, 요청에 계좌번호를 보내지 않는다.)

**2. 디스코드 봇** — [Developer Portal](https://discord.com/developers/applications)에서 봇 생성 →
봇 토큰 발급 → OAuth2 URL Generator에서 `bot`, `applications.commands` 스코프로 본인 서버에 초대.
봇 아이콘은 `assets/icon_512.png`를 General Information과 Bot 탭에 업로드.

**3. ID 확인** — 디스코드 개발자 모드를 켜고 본인 프로필과 사용할 채널의 ID를 복사.

**4. 환경 변수** — `.env.example`을 `.env`로 복사 후 값 입력.

```
KIWOOM_APP_KEY=...
KIWOOM_APP_SECRET=...
KIWOOM_ACCOUNT_NO=...           # 표시용
KIWOOM_IS_MOCK=false            # 모의투자는 true
DISCORD_BOT_TOKEN=...
DISCORD_OWNER_ID=...            # 본인 디스코드 ID
DISCORD_ALLOWED_CHANNEL_ID=...  # 봇을 쓸 채널 ID
```

**5. 포트폴리오** — `data/portfolio.json`에 실제 ETF 종목을 작성. 종목코드(`ticker`)는
키움 계좌의 실제 코드와 일치해야 하며, 비중(`weight`) 합계는 1.0이어야 한다.

이 파일이 곧 **전략 종목의 정의**다. 여기에 없는 종목은 봇이 주문하지도, 집계에 넣지도
않는다. 반대로 여기에 적으면 그 종목은 리밸런싱 매수와 미체결 재주문의 대상이 된다.

## 실행

**평소 사용** — `start.vbs`를 실행하면 콘솔 창 없이 트레이에 아이콘이 뜬다.
아이콘에 마우스를 올리면 `isaflow-bot · 정상 · 가동 3시간 12분` 처럼 상태가 보인다.

| 아이콘 색 | 상태                      |
| --------- | ------------------------- |
| 회색      | 시작 중 / 중지됨          |
| 주황      | 네트워크 대기 · 재연결 중 |
| 원래 색   | 정상 (명령어 수신 가능)   |
| 빨강      | 오류 — 우클릭 → 로그 보기 |

우클릭 메뉴: **로그 보기**(메모장으로 `logs/bot.log` 열기) · **로그 폴더 열기** ·
**봇 재시작** · **종료**. 로그 창은 실시간 갱신이 아니므로, 최신 내용을 보려면 닫고 다시 연다.

**부팅 시 자동 실행** — `Win + R` → `shell:startup` 으로 폴더를 열고
`start.vbs`의 **바로가기**를 넣는다. (원본이 아니라 바로가기를 넣어야 나중에 옮기기 편하다)

> 시작프로그램은 **로그온 후에** 실행된다. 정전이나 윈도우 업데이트로 재부팅됐을 때도
> 봇이 뜨게 하려면 `Win + R` → `netplwiz` 에서 자동 로그온을 켜 둔다.

**디버깅** — 문제가 생기면 `run.bat`을 더블클릭한다. 기존처럼 콘솔에 로그가 흐른다.

```bash
uv run python main.py --console
```

봇을 종료할 땐 트레이 아이콘 우클릭 → 종료(콘솔 모드는 `Ctrl+C`).
키움 토큰은 자동 발급·갱신된다.

## 처음 사용 시

1. `.env`의 `KIWOOM_IS_MOCK=true`로 모의투자에서 먼저 테스트
2. `/포트폴리오` → `/계좌현황`으로 조회 기능 확인
3. `/매수`는 소액으로 시도, 취소 버튼 동작도 확인
4. 키움 앱에서 체결 내역이 일치하는지 확인 후 `KIWOOM_IS_MOCK=false`로 전환
5. 계좌에 전략 외 종목이 있다면 `/계좌현황`에 `👀 전략 외 보유` 섹션이 뜨는지,
   `/미체결`에서 그 종목이 재주문 대상에서 빠지는지 확인

> 매수는 한국 주식시장 정규장 시간(평일 09:00~15:30)에만 체결된다.

## 자주 발생하는 문제

| 증상                    | 해결                                                    |
| ----------------------- | ------------------------------------------------------- |
| 토큰 발급 실패          | 앱키·시크릿 오타, 또는 API 신청 미승인                  |
| 보유 종목이 안 나옴     | 키움 마이페이지에서 ISA를 기본 계좌로 설정              |
| 슬래시 커맨드가 안 보임 | 봇 초대 시 `applications.commands` 스코프 누락 — 재초대 |
| 봇은 온라인인데 무응답  | `DISCORD_OWNER_ID` / `DISCORD_ALLOWED_CHANNEL_ID` 확인  |
| 매수 후 미체결          | 조회~주문 사이 호가 변동 — `/미체결`로 재주문           |
| 트레이 아이콘이 안 뜸   | `run.bat`으로 콘솔 모드 실행해 오류 확인                |
| 아이콘이 계속 주황      | 인터넷 연결 확인 — 붙는 즉시 자동으로 정상 전환         |
| 아이콘이 빨강           | 우클릭 → 로그 보기로 원인 확인 후 봇 재시작             |
| "이미 실행 중입니다"    | 트레이에 이미 떠 있음 — 중복 주문 방지용 차단           |
| 분배금이 안 나옴        | 키움이 분배금을 "수익분배금입금" 적요로 처리하는지 확인 |
| 보유 종목이 전략 외로 분류됨 | `data/portfolio.json`의 `ticker`가 키움 종목코드와 일치하는지 확인 |
| 비중이 전부 부족해 보임 | 구버전 — 분모가 계좌 전체였다. 최신 `account.py` 적용 확인 |
| 호출 한도(429) 오류     | 자동 재시도 후에도 실패한 경우 — 잠시 후 다시 시도        |

자세한 오류는 `logs/bot.log`에서 확인할 수 있다.

## 기술 스택

discord.py · httpx · matplotlib · pystray · Pillow · python-dotenv · uv

키움 API: `au10001`(토큰), `kt00018`(잔고), `kt00001`(예수금), `kt00015`(거래내역),
`ka10001`(현재가), `ka10004`(호가), `kt10000`(매수주문), `kt10003`(주문취소), `ka10075`(미체결)

모든 호출은 `kiwoom/client.py`의 단일 경로를 지나며 최소 0.6초 간격으로 직렬화된다.
429·5xx는 `Retry-After`를 존중해 지수 백오프로 재시도하되, **주문 API는 5xx에서 재시도하지
않는다** — 서버가 이미 접수했을 수 있어 중복 주문이 되기 때문이다.

## 보안

`.env`에는 실제 자산을 움직이는 키가 들어있으니 외부에 공유하지 않는다.
봇은 본인 계정이 지정 채널에서 쓸 때만 동작하며, 비공개 서버 운영을 권장한다.
모든 매수 명령은 `logs/bot.log`에 기록된다.
봇은 `data/portfolio.json`에 적힌 종목에만 주문을 걸므로, 같은 계좌의 다른 전략 종목은
봇의 조작 대상이 아니다.
